# Deploying `mpikipiki`

Flask + MongoDB ride-hailing prototype: signup/login with roles
(customer / driver), ride requests with haversine distance matching, driver
availability, trips.

| Fact | Value |
|---|---|
| WSGI entrypoint | `deploy_wsgi:app` (calls `create_app()`, adds `/healthz`) |
| Listens on | `5759` inside the container |
| Suggested hostname | `rides.harolditdata.uk` |
| Persistent state | MongoDB (external), database `ridehailing` |
| Status | **prototype** — see section 5 |

---

## 0. `python app.py` does not work, and that is expected

`app.py` does `from . import create_app` — a relative import in a file run as a
top-level script, which raises
`ImportError: attempted relative import with no known parent package`.

Working invocations:

```bash
flask --app "app:create_app" run          # development
gunicorn deploy_wsgi:app                  # production (what the image does)
```

Both resolve `app` to the **package** `app/`, not to `app.py`: a package
shadows a same-named module on the path. `deploy_wsgi.py` was added rather than
editing `app.py`.

## 1. BLOCKERS — read before pointing DNS at it

**(a) Committed credentials.** This repo has no `.gitignore`, and `.env` **is
tracked by git** (`git ls-files` confirms it). It contains real-shaped PayPal,
M-Pesa and Airtel Money client IDs, secrets, shortcodes and passkeys.

- None of those variables are referenced anywhere in this codebase — the file
  looks copy-pasted from `carbon-foortprint`. They are leaked for nothing.
- Rotate every one of them at the provider, then remove the file from history
  (`git filter-repo` / BFG) and add a `.gitignore`.
- The `.dockerignore` added here keeps `.env` out of the image, but that does
  not un-leak it from the repository.

**(b) Prototype-grade code.** `app/g.py` is a stray code-generation scratch
script for an unrelated cosmetics site that writes to `/home/harold/Desktop/...`
at import. It is never imported, and the `.dockerignore` excludes it, but it
should be deleted.

## 2. Environment variables

Derived from the code. Everything in the committed `.env` beyond these three is
noise.

| Variable | Required | Default | Read by | Notes |
|---|---|---|---|---|
| `MONGO_URI` | **Yes** | `mongodb://localhost:27017/ridehailing` (hardcoded in `app/__init__.py`) | `deploy_wsgi.py` | Must include a database name, e.g. `mongodb://mongo:27017/ridehailing` or a `mongodb+srv://…/ridehailing` Atlas URI. `deploy_wsgi.py` rebinds `mongo.cx` / `mongo.db` after `create_app()`, because `mongo.init_app()` has already consumed the hardcoded value. Collections used: `users`, `rides`, `drivers`, `trips`. |
| `SECRET_KEY` | **Yes** | `"supersecretkey"` (hardcoded in `app/__init__.py`, with a TODO comment) | `deploy_wsgi.py` | Signs session cookies and Flask-WTF CSRF tokens. Generate with `python -c "import secrets; print(secrets.token_hex(32))"`. |
| `PORT` | No | `5000` in `app.py`, `5759` in the image | `app.py`, `Procfile` | Ignored by the Dockerfile, which binds 5759. |
| `PAYPAL_*`, `MPESA_*`, `AIRTEL_MONEY_*`, `CORS_HEADERS` | No | — | **nothing** | Present in the committed `.env`, referenced by zero lines of code. Do not carry them forward. |

The cleaner fix — which this deployment pass deliberately did not make, because
it would mean editing application source — is two lines in `app/__init__.py`:

```python
app.config["SECRET_KEY"] = os.environ["SECRET_KEY"]
app.config["MONGO_URI"]  = os.environ["MONGO_URI"]
```

Once that lands, `deploy_wsgi.py`'s overrides become no-ops and can stay.

## 3. Build and run

```bash
docker build -t mpikipiki:latest .

docker run -d --name mpikipiki \
  --restart unless-stopped \
  --read-only \
  --tmpfs /tmp:rw,noexec,nosuid,size=32m \
  -p 127.0.0.1:5759:5759 \
  --env-file /etc/harold/mpikipiki.env \
  --memory 300m --cpus 0.5 \
  mpikipiki:latest
```

The app writes nothing to disk — all state is in MongoDB — so `--read-only` is
safe here.

`requirements.txt` **was generated by this deployment pass** from the actual
imports in `app.py` and `app/*.py`; the repo had none. The header of that file
lists which module each dependency comes from.

## 5. Why this is not "host now"

- It stores third-party personal data: names, emails, **phone numbers**, and
  pickup/dropoff coordinates of riders and drivers.
- Passwords use `werkzeug.security` hashing (good) and CSRF is on (good), but
  there is no rate limiting, no email verification, no account lockout, and
  `login_manager.login_view` is the only access control.
- It is a prototype that has, by the owner's own account, never been run as a
  service.

If you want it reachable before that is addressed, put a **Cloudflare Access**
policy in front of the hostname so only your own identity can open it.
